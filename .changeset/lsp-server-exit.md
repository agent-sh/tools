Report a language server that exits instead of hanging on it. A request in flight when the server process exits now rejects at once with `LspServerExitedError`, which carries the exit code or signal and the last 4 KB of the server's stderr, and the `lsp` tool returns `SERVER_CRASHED` for that call. `ensureServer` rejects when the server exits or fails to spawn during `initialize`, and `initialize` is bounded by `DEFAULT_INITIALIZE_TIMEOUT_MS`, the 60s session backstop, which outlasts the 30s call budget (`initializeTimeoutMs` on `createSpawnLspClient` overrides it). The client now drains the server's stderr, so a server that writes a lot of it can no longer block. A server whose stdin breaks after startup is marked crashed and stopped, so the next call starts a new one instead of reusing a server that cannot be reached. A server whose stdout closes while it stays alive is retired the same way after a 2s grace. The call that finds a broken pipe now gets `SERVER_CRASHED` (`LspServerCrashedError`, the new base class of `LspServerExitedError`). `ensureServer` takes the call's signal, so the `lsp` tool's timeout covers a slow start; the server keeps starting and the next call gets `server_starting`. A start that fails after its call gave up is reported once to the next call as `SERVER_NOT_AVAILABLE`, with the exit code or signal and the stderr tail. A call cancelled through the session signal now says so, and one whose signal is already aborted starts no server.

Breaking: `ServerHandle.state` no longer includes `crashed`, which `ensureServer` never returned. Code that compares the state with `"crashed"`, or an `LspClient` adapter that returns it, no longer compiles; an adapter should throw `LspServerCrashedError` instead.
